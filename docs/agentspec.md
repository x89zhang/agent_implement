# AgentSpec

AgentSpec is an optional, tool-call runtime-enforcement middleware. It is
disabled by default and is independent of Pro2Guard and the other guards.

This integration follows AgentSpec's own execution model: a rule is selected by
its trigger, its predicates inspect the user request, proposed tool input, and
prior tool trajectory, and its enforcement determines what happens next. It is
not reduced to a generic block score.

## Installation

For a non-container run, install the main requirements and then the authors'
repository pinned by this project:

```bash
pip install -r requirements.txt
pip install -r requirements-agentspec.txt
```

Do not use `pip install agentspec`. That PyPI name belongs to an unrelated
project. The research repository currently builds a distribution named
`agentspec`, but exposes top-level modules such as `rule`, `interpreter`, and
`state`; the adapter handles that upstream layout.

Nothing under `paper/AgentSpec` is imported at runtime. That directory is only
a local paper/reproduction snapshot and may be removed without affecting an
installed deployment.

## Container and AgentDojo runs

When `container.enabled` is true, installing AgentSpec on the host is not
sufficient: the middleware is imported by the Python process inside the Agent
container. Before starting a container with `agentspec.enabled: true`, the
container runner probes the selected image for the upstream `rule` and
`interpreter` modules. If they are missing and `container.auto_build` is true,
it automatically rebuilds the image with `INSTALL_AGENTSPEC=true`.

For example, an AgentDojo configuration can keep its benchmark build argument
and simply enable AgentSpec:

```yaml
container:
  image: agent-scaffold-agentdojo:latest
  auto_build: true
  build_args:
    INSTALL_AGENTDOJO: "true"

agentspec:
  enabled: true
  generator:
    enabled: true
    context_mode: benign_only
    max_attempts: 2
    max_rules: 12
```

No hand-written rule file is required in this mode. The LLM generates the rules
inside the task container, and the installed upstream parser validates them before
the agent graph is built. Generated input, raw response, DSL, and manifest files
are retained in the job directory. Static `rules` and `rule_files`, when present,
are appended to the generated rules. Set `generator.enabled: false` to use only
manual rules.

`INSTALL_AGENTSPEC=true` is injected automatically. The resulting image is
cached and reused on later tasks after the import probe succeeds. With
`container.auto_build: false`, build the custom image explicitly with
`--build-arg INSTALL_AGENTSPEC=true`.

## Configuration

Rules are generated by default whenever AgentSpec is enabled. The generator uses
the main `llm` configuration unless its optional `llm` mapping overrides provider,
model, temperature, base URL, API key, or request timeout. `benign_only` is the
default for AgentDojo and intentionally excludes hidden injection metadata.

For a manual-only setup, disable generation; rules may be inline or loaded
relative to the harness configuration directory:

```yaml
agentspec:
  enabled: true
  generator:
    enabled: false
  rule_files:
    - rules/agentspec/code.ar
  rules:
    - |
      rule @inspect_python
      trigger
          python_repl
      check
          involve_system_file
          destuctive_os_inst
      enforce
          user_inspection
      end
  approval_handler: prompt
  max_reflections: 3
  fail_closed: true
```

Each inline entry should contain one rule. A rule file may contain multiple
`rule ... end` blocks. Trigger names must match scaffold tool names exactly,
consistent with AgentSpec's documented behavior.

`approval_handler` controls `user_inspection`:

- `prompt` uses an interactive yes/no terminal prompt.
- `package.module:function` imports an application callback. It receives
  `rule_id`, `event`, `tool_name`, `arguments`, and `state`, and returns a truthy
  value to approve the action.

`predicate_modules` can register application predicates into AgentSpec's
upstream predicate table. Each entry is either a mapping import or a callable
that accepts the table:

```yaml
agentspec:
  predicate_modules:
    - my_agent.predicates:PREDICATES
    - my_agent.registration:register_agentspec_predicates
```

The predicate name must also be recognized by the generated grammar shipped by
the pinned AgentSpec revision. Upstream currently requires regenerating its
parser when adding a new predicate token.

## Enforcement mapping

- `none`: execute normally.
- `skip`: do not execute the proposed call; return an observation to the agent.
- `stop`: do not execute the call and terminate the current run.
- `user_inspection`: execute only when the configured approval path approves.
- `llm_self_reflect` / `llm_self_examine`: do not execute the call; return rule
